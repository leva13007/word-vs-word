# 0004. specify vs clarify vs define vs refine

> 🔧 IT

Усі ці дієслова звучать як «пояснити», але насправді описують різні етапи роботи з вимогами та документацією. Розкладемо процес від сирої ідеї до затвердженого рішення.

## Одним поглядом

| Слово | Значення (UA) | Ключовий нюанс |
|-------|--------------|----------------|
| **define** | визначити | окреслити межі поняття, глосарій |
| **specify** | вказати / уточнити | конкретні значення, формат, обмеження |
| **clarify** | прояснити | прибрати двозначність після питання |
| **detail** | деталізувати | кроки і послідовність |
| **refine** | відшліфувати | покращити після фідбеку |

---

### Мислимо як інженери

```
IDEA (в тумані)
  ↓ define (що це взагалі?)
SPECIFY (чіткі параметри)
  ↓
CLARIFY (знімаємо двозначність)
  ↓
DETAIL / REFINE (розкладаємо кроки, шліфуємо)
  ↓
CONFIRM (фіксуємо спільне розуміння)
```

Кожне слово має свій момент у цьому циклі. Якщо обираємо правильне — команда розуміє, на якому етапі знаходимося.

---

### define — окреслити поняття

**Суть:** Пояснити, що означає термін або об’єкт загалом. Без деталей, лише межі поняття.

- перший крок перед будь-якою конкретикою
- часто формує глосарій або контракт термінів

**В ІТ:**

- define what “active user” means
- define service-level objectives
- define roles у доступах

**Приклад:** `We need to define what counts as a “failed login attempt.”`

**Як думаємо:** «Про що ми взагалі говоримо?»

---

### specify — зафіксувати точні параметри

**Суть:** Перетворити ідею або термін на конкретні значення, правила, формати.

- звучить формально й остаточно
- зазвичай трапляється до початку реалізації

**В ІТ:**

- specify request/response schema
- specify feature requirements
- specify allowed parameter ranges

**Приклад:** `Please specify the exact JSON structure we should return.`

**Як думаємо:** «Які саме цифри, поля, обмеження?»

---

### clarify — прибрати двозначність

**Суть:** Уточнити те, що вже було сказано, щоб усі зрозуміли однаково.

- реактивне слово — з’являється після питання/непорозуміння
- не додає нових вимог, а розкриває існуючі

**В ІТ:**

- clarify expected behavior on error
- clarify acceptance criteria
- clarify owner responsibilities

**Приклад:** `Could you clarify what should happen if the billing service times out?`

**Як думаємо:** «Що саме ти мав на увазі тоді?»

---

### detail — розписати кроки

**Суть:** Додати дрібні частини, послідовність, інструкції всередині вже заданих меж.

- відповідає на «як саме це робимо»
- хороше слово для документації, runbook-ів, чеклістів

**В ІТ:**

- detail deployment steps
- detail migration plan
- detail user flows

**Приклад:** `The runbook details every step required to fail over the cluster.`

**Як думаємо:** «Якою конкретно послідовністю дій це робимо?»

---

### refine — відшліфувати після фідбеку

**Суть:** Покращити, зробити точнішим або зручнішим уже існуючий опис / вимогу.

- завжди спирається на результат рев’ю чи експериментів
- може включати видалення зайвого, додавання крайових кейсів

**В ІТ:**

- refine the API contract after review
- refine ML features based on experiments
- refine acceptance criteria після прототипу

**Приклад:** `We refined the pagination rules once QA uncovered edge cases.`

**Як думаємо:** «Як покращити вже написане, щоб воно працювало?»

---

### Порівняльна таблиця

| Verb | Момент | Мета | Ключове питання |
|------|--------|------|-----------------|
| define | старт | встановити межі поняття | `Про що мова?` |
| specify | перед реалізацією | задати точні параметри | `Які значення/формати?` |
| clarify | після опису | прибрати двозначність | `Що ти мав на увазі?` |
| detail | перед виконанням | розкласти на кроки | `Як саме це робимо?` |
| refine | після фідбеку | довести до точності/зручності | `Що треба покращити?` |

---

### Сусідні дієслова

- `elaborate` — дати більше контексту, історії (не завжди точніше): `Could you elaborate on the rollout approach?`
- `confirm` — зафіксувати спільне розуміння після всіх уточнень: `Let’s confirm the final requirements before implementation.`

---

### Один сценарій

`We defined what “premium seat” means, specified the API parameters, clarified the error handling rules after Q&A, detailed the rollout checklist, refined the docs after a design review, and finally confirmed the requirements with stakeholders.`

---

### Типові помилки

- `clarify requirements` — якщо їх ще не існує; спочатку треба `specify requirements`.
- `specify what you meant` — коли проблема у двозначності, краще `clarify what you meant`.
- `refine before feedback` — слово має сенс лише тоді, коли вже є результат рев’ю або експеримент.

---

### Мнемоніка

- define → 📘 термін
- specify → 🎯 параметри
- clarify → 🔍 сенс
- detail → 📋 кроки
- refine → 🪚 шліфуємо
---

## Для картки

> `(...)` — безпечний контекст. `(~...~)` — не перекладати дослівно. `(A|B)` — альтернативи.

| Слово | Запис на картці |
|-------|------|
| **define** | `визначити (~окреслити поняття~)` |
| **specify** | `уточнити (параметри)` або `вказати (~конкретно~)` |
| **clarify** | `прояснити (~прибрати двозначність~)` |
| **detail** | `розписати (~покроково~)` |
| **refine** | `відшліфувати (~після фідбеку~)` |
